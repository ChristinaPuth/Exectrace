## 3. Issue: the chat cache was invalidated by line endings

**What happened.** The acceptance run re-asked all 34 evaluation questions
with real model calls ("Answers from the cache: 0 of 34"), which I had not
planned.

**Cause.**
- To merge M5 into `main`, I checked out `main`, which was still at M4.
  `agent.py` and `sqlguard.py` don't exist there, so the merge re-created
  them.
- This machine's Git setting `core.autocrlf=true` wrote them with Windows
  line endings.
- The chat cache key includes a hash of those two files' bytes, so no key
  matched.

**Fix.**
- A new `.gitattributes` pins text files to LF line endings on every
  platform. The working copy was rewritten to match the repository, which
  already held LF.
- Asked again with model calls blocked, the evaluation found all 34 answers
  in the cache: 31 of 31, claim-level check 34 of 34.

No code changed.

**What the fresh answers showed.** This was the first time all 34 questions
were answered fresh since M5. 30 of 31 passed. The failure was rh12, "Where
is the CEO based?": it correctly said the location was not found, but cited
an SEC URL anyway, against the rule "when nothing was found, cite nothing".
The committed results file holds the cached answers (31 of 31), and the log
holds this run. The README states both.

## 5. Session export

`tools/export_session.py` copies this project's Claude Code transcripts from
`~/.claude/projects/` into `session/`, one file per session, oldest first,
and writes `session/index.md`. Every e-mail address and every `.env` value
of 8 or more characters is replaced by `[REDACTED]`. The exceptions are
Anthropic's commit address and placeholder addresses at example.com and
example.org.

- 5 transcripts, about 39 MB. The secret scan passes on them.
