## 5. Decisions made during M2 that the spec did not fix

**Reviewed by you on 2026-11-12: all twelve accepted, with two caveats that
M3 must address.**

- **On decision 9:** a page naming the company's domain does not prove it
  belongs to the same company. The lookalike check is only a first filter.
  The real check is per person, in extraction (checklist R150).
- **On decision 10:** a list of excluded sites cannot be maintained
  indefinitely. M3 needs a rule that does not depend on site names
  (checklist R153): a claim supported only by third-party profile, directory
  or summary pages cannot make a role `current`.

1. **Working database** is `data/leadership.db` (not committed). The
   committed fixture in `fixtures/` is produced by the export step in M4.
2. **A second model decision in collection:** which search results are about
   this company (issue 3). The spec had one (which site links to read).
3. **What the page budget counts:** stored sources only. `robots.txt`,
   sitemaps and the SEC and Wikipedia lookups are not counted; they are
   bounded separately (`[discovery]` in `config.toml`).
4. **Definite refusals are cached.** A 403 or 404 is remembered, so the page
   is not requested again. Timeouts, 429 and 5xx are never cached.
5. **Honest identification.** The fetcher identifies itself as
   `ExecTraceBot/0.1`. It never imitates a browser to get past a block.
6. **`insufficient_data` in M2** means no company page other than the
   homepage could be read. The people-based meaning (no CEO found) is M3.
7. **Exit codes of `collect`:** 0 for `complete`, 3 for any other final
   status, 1 when the homepage is unreachable.
8. **SEC matching is strict:** the registrant's name must equal the company's
   name once words like "Inc." and "Markets" are removed, and its listed
   website, if any, must be the same domain. "Campfire" matched nothing.
9. **Lookalike sites need proof** (issue 9). The proof is the page naming
   one of the company's own domains. An excluded page is kept as a `skipped`
   row with the reason, so the exclusion can be reviewed; it is not a
   failure and does not change the run status.
10. **Original sources only.** Generated summary pages from search and AI
    companies (`tavily.com`, `exa.ai`, `vectorshift.ai`, `derrick-app.com`) are
    never fetched or stored. The list is four named sites in `leadership/collect.py`; a new one would have to be
    added by hand. No link is followed from these pages either: other sources
    are found through the search results themselves.

11. **A refused page is not a failure** (issue 11). The run stays
    `complete`. `access_refused` is a new reason code that never changes the
    status; it is recorded only for the company's own pages and filings
    (tier 1 and 2). Third-party refusals appear in the report list only.
12. **Many sources now have no date** (issue 12): for Campfire, 3 of 10
    fetched articles; company pages never had one. Undated tier-3 sources
    count as weak under the M1 rules, which is the intended, cautious result.
