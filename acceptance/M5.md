## 3. How it works

- **One tool**, `query_db(sql)`, at most 5 model calls per question and 2 SQL
  retries, then an honest failure. A final answer is accepted only after at
  least one query succeeded; otherwise the agent says it could not look the
  answer up and does not answer from memory.
- **SQL guard.** When a chat starts, the two views are copied into a
  separate snapshot database holding only `leadership` and
  `current_leadership`. It is opened read-only, and an authorizer allows
  reading those tables and nothing else: no schema, `PRAGMA`, `ATTACH`,
  writes or DDL. One statement per call, 50 rows, 5 seconds.
- **The prompt** gives the company's run status and collection date, the
  columns and allowed values, five example queries and the answering rules
  of SPEC 5. It tells the model to trust the status columns rather than work
  out a status from dates in quoted text.
- **Incomplete data.** If the company's run status is not `complete`, the
  prompt says so and every answer must say the data is incomplete (special
  case run01). The command line also prints the status.
- **Sources.** The model is asked to cite a URL for every person it names.
  When it gives only the source type and date, the source URLs of the named
  people are appended under "Sources:" from the rows the agent queried. This
  is done in code and adds nothing the rows did not contain.
- **Chat log** (`logs/chat-<domain>-<time>.jsonl`): each question, every
  model call, every SQL attempt with its row count and error, and the
  answer.

## 4. Errors and issues met during M5

| # | What happened | Cause | Resolution |
|---|---|---|---|
| 1 | A guard that allowed "reads through the views" refused every query | SQLite reports some reads inside the views' subqueries without the view's name, so they look like direct reads of base tables | The agent reads a snapshot holding only the two views (section 3). Stricter than planned: the base tables do not exist for it |
| 2 | **A wrong answer in the first evaluation:** "Jason Warnick is still at Robinhood ... will remain until Sept. 1, 2026" | The model read the date from the quoted text and ignored `employment_status = former`; the date had passed | The prompt gives the collection date and says statuses are already decided and must be trusted. Now: "Jason Warnick is no longer at Robinhood" |
| 3 | "Who was the previous CFO?" named Warnick but not when he left, and cited a 2020 press release | The view had no link to the source that ended a role | The view gained `ended_by_source_url`, `ended_by_source_date` and `ended_by_evidence`; the prompt asks for the end date and that source. Now: "effective 2026-02-06", citing the SEC proxy |
| 4 | A "not found" answer carried a citation | Prompt | "When nothing was found, cite nothing" |
| 5 | The C-level answer named five people without URLs | The model gave source types and dates only | Sources appended from the queried rows (section 3). No further model call |
| 6 | Four correct answers were graded as failures | My grader: curly apostrophes ("couldn’t find"), "do not list", and a URL inside markdown italics | Grader fixed; tests added. Re-graded from the cache |

Issue 2 is the one that matters: the model contradicted the data with a
plausible reading of a quote. The fix is in the prompt, so it reduces the
risk but does not remove it; the evaluation now checks this case.

**Fixes after the first review.** All four are in code outside `agent.py` and
`sqlguard.py`, so the cached answers stay valid and no new model call was
needed. Each has a regression test in `tests/test_chat.py`.

| # | What was found | Fix |
|---|---|---|
| 7 | The previous-CFO answer cited the SEC filing that ended Warnick's role, but a 2020 press release about another executive's hire was still appended as his source (citation review item 4) | A person cited by any of their URLs (including the source that ended the role) gets nothing appended. When a source is appended for a former role, it is the one that ended it. A surname shared by two queried people no longer counts as naming either. Citations now: 28 URLs, 0 foreign |
| 8 | Only the selected company's data must be readable | Already so: the snapshot holds one company's rows. Now tested for both companies: the other company's people, domain and base tables cannot be read, and the prompt does not mention the other company |
| 9 | The command-line chat stopped only on an empty line | `exit`, `quit`, `q` and `bye` also stop it |
| 10 | "0 vice presidents found in public sources" for Robinhood reads as "Robinhood has none", although 29 of its sources, 15 on its own site, could not be read | After a count, a note says the count covers only sources that could be read, how many could not be, and, for 0, that none found does not mean none exist. It is added in code from the database, after the model's answer |

## 5. Decisions made during M5 that the spec did not fix

Please confirm or change these in manual test MT-5.8.

1. **The guard is a snapshot** of the two views (issue 1), not an authorizer
   on the full database.
2. **A final answer needs at least one successful query**; otherwise "I could
   not look this up".
3. **Answers are cached** by question, prompt, model, data and code, so
   asking the same question again costs nothing and gives the same answer.
4. **Sources are appended in code** when the model leaves out URLs
   (issue 5).
5. **The four sample questions** are the ones in section 2.
6. **Reference questions were drafted by Claude** for you to review
   (`fixtures/chat_eval.json`, MT-5.7), as with the gold sets.
7. **Grading is by rules, not by a model**: named people by surname, counts,
   "not found" and caveat wording, and URL ownership. It can be fooled by an
   answer that has the right words for the wrong reason, which is why the
   manual citation review exists.

## 6. Limitations

- **The model is not fully repeatable.** Two runs of the same question can
  differ; the cache makes a given answer stable, not right.
- **Prompt rules reduce, not remove, misreadings** (issue 2).
- **The answers inherit the data's gaps.** For Robinhood the chat knows 5
  C-level leaders and no vice presidents (M4); it says "not found" for the
  rest, correctly from the data but not from the world.
- **Rule-based grading** (decision 7).
- **The command line only.** The Streamlit UI is M6.
